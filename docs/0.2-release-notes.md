# rusthinq 0.2 release notes (draft)

Status: draft. 0.2 is not released; the remaining gates are in
[milestones](0.2-milestones.md). Real appliances and LG accounts have not been used to
validate 0.2 (excluded at the maintainer's request), and no ThinQ1 appliance was available.

## What changes for a 0.1 user

- **One daemon, new internals.** Protocol and lifecycle decisions run in pure cores; one
  application runtime owns sessions, scripts, persistence and the LG bridge. Device and
  LG cloud wire behavior is preserved (see the L1 compatibility table and
  [non-inferiority audit](0.2-non-inferior.md)).
- **No external broker required.** The dashboard, device monitor and management API work
  without MQTT. External MQTT is optional and survives broker outages: retained state is
  republished on reconnect without clearing it, and non-retained output during an outage is
  dropped and counted (`GET /api/mqtt` → `droppedTransient`).
- **rusthinq is IL-agnostic.** The host knows no device semantics. IL descriptors, values,
  validation and rejects live in rusthinq-scripts' `il_common.rhai`; commands reach
  `on_set_property` unvalidated. The `[scripting] il_prefix` setting is gone; the
  descriptor prefix is set in `il_common.rhai` (default `il`, per il-mqtt M-1).
- **Durable, owned state.** Device incarnations, retained-topic ownership and cloud
  registrations are persisted; forget and retained deletion are confirmed, restart-safe
  operations.
- **Firmware passthrough** relays learned download hosts to their real servers. As in 0.1,
  a name refused once is suspected for 60 seconds, so the appliance's retry passes through.
- **Tools** are consolidated in `rusthinq-tools` (`rusthinqctl`, MCP, capture/replay,
  packet tools, SoftAP setup, retained GC, driver test runner, migrator).

The full surface-by-surface classification is the
[compatibility inventory](0.2-compatibility.md).

## Upgrading

1. Stop nothing yet. Run `rusthinq-migrate OLD_CONFIG NEW_DIRECTORY`; it stages a
   converted installation and never modifies 0.1 files.
2. Read the report's `warnings` and finish the settings it lists (external MQTT,
   management bind/authentication, proxy/root/DNS settings).
3. Update rusthinq-scripts to the `il_common` revision. 0.1-era drivers call
   `ctx.publish_il`, which 0.2 no longer provides.
4. Stop 0.1, start 0.2 on the staged directory, then adopt archived cloud registrations per
   device (`POST /api/devices/{id}/bridge/adopt`); they are imported disabled.

## Rolling back

Stop 0.2 and start 0.1 on the untouched original configuration and state. Check out
rusthinq-scripts at `54292921c6edc72ea6ec901b1137845bff14e6ae` (pre-`il_common`): the
`il_common` drivers do not run on 0.1. Retained topics published by 0.2 under the `il`
descriptor prefix are not removed by 0.1. Clear them with `rusthinq-retained-gc` before
rolling back, or remove them at the broker.

## Known limits

- The LG bridge is verified end to end against a fake LG service only (account API and
  MQTT); no real LG account was used.
- ThinQ1 is verified at the protocol level only, including byte parity of command frames
  with 0.1.
- There are no log categories: application events go to stderr.

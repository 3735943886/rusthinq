# 0.2 코드 정리

현재 워크스페이스의 7개 크레이트와 GUI를 대상으로 저장, 작업 소유권,
알림 버퍼, 캡처, 프로토콜 유틸리티의 중복과 수명 관리를 정리했다.
`legacy/0.1`은 비교·마이그레이션용 보관본으로 유지한다.
Rhai 함수, 드라이버 파일, 지원 모델은 추가하지 않는다.

## 저장소의 공통 소유자

`rusthinq-app/src/checkpoint.rs`는 계정, lifecycle, pairing, retained cleanup
저장소에서 반복되던 다음 절차를 담당한다.

- 소유 기간 동안 sidecar 파일 잠금 유지. 잠금 파일은 삭제하지 않는다.
- 최대 크기보다 1바이트 더 읽어 초과 여부 판별.
- 같은 디렉터리의 임시 파일에 쓰고 파일 동기화 후 원자적으로 교체.
- 부모 디렉터리 동기화까지 성공한 뒤 도메인 상태를 갱신.
- 쓰기 실패 후 재열기 전까지 후속 쓰기 차단. 교체 후 디렉터리 동기화가
  실패했을 수도 있으므로 성공 여부를 임의로 추정하지 않는다.

잠금 파일과 임시 파일은 파일 소유자 및 `tempfile`의 RAII로 정리한다.
각 저장소의 스키마, 검증, 세대 예약, 페어링 소유권, 삭제 확인 정책은
해당 도메인 모듈에 둔다. 이 공통 모듈이 디바이스 의미를 해석하지 않는다.

## 비동기 작업의 소유권

`rusthinq-app/src/task.rs`의 `OwnedTask`는 `JoinHandle`을 감싼 내부 타입이다.
정상 경로에서는 기존처럼 작업 완료를 기다린다. 소유 Future가 취소되거나
중도 반환하면 `Drop`이 비동기 작업의 abort를 요청해 작업 분리를 방지한다.
`Shutdown`은 명시적 종료와 소유자 해제 모두에서 watch 종료 신호를 보낸다.

적용 대상은 daemon의 signer/core, TLS lifecycle runtime, management의 이름
갱신·LG observer, 기기별 cloud supervisor, lifecycle cleanup 작업이다.
정상 종료에서 기기 종료 출력 → 외부 MQTT flush → 부가 서비스 종료 순서를
유지한다. `JoinSet`으로 이미 소유하던 작업은 그대로 관리한다.

`Drop`은 비동기로 join할 수 없으므로 완료 대기까지 보장하지 않는다.
실행을 시작한 `spawn_blocking` 작업도 abort로 강제 중단할 수 없다.
파일·암호화·스크립트 작업의 정상 종료는 기존의 명시적 await 경로가 담당한다.

## 알림과 진단 캐시

LG 기록은 JSON 외에 정수 순번과 직렬화 크기를 저장한다. 페이지 조회에서
순번 문자열을 반복 파싱하지 않고, 퇴출 시 JSON을 다시 직렬화하지 않는다.
REST와 WebSocket이 같은 기기 필터를 사용하고, 상태는 내부 enum으로 표현한다.
외부 상태 문자열과 큰 순번의 문자열 표현은 유지한다.

기록·reset의 상태 변경과 broadcast를 같은 mutex 구간에서 처리한다.
기록을 삭제한 뒤 이전 기록이 늦게 broadcast되는 순서 경쟁을 제거했다.
완성된 envelope에 크기 제한을 적용하고, 잘못된 입력은 순번을 소비하지 않는다.

publication 캐시는 scope와 항목별 크기를 보관한다. 전체 크기를 매번 합산하는
대신 갱신·삭제·scope 교체·기기 제거 시 사용량을 반영한다. 같은 topic의 값
교체는 이전 크기를 뺀 후 판정한다. 한도 근처에서 정상 갱신이 잘못 거부되고
해당 기기 캐시가 삭제되던 문제를 수정했다.

## CLI와 캡처

`rusthinq-tools/src/capture.rs`로 wire/LG 캡처와 관찰 코드를 분리하고 기존
crate 루트의 공개 함수는 재export한다. `EventStream`으로 WebSocket 타입을
한 번 정의한다. JSONL 쓰기·flush와 LG 연속성 판정을 각각 모은다.
캡처 파일 쓰기와 adoption archive 읽기는 Tokio 파일 API를 사용한다.

LG stream의 EOF, Close, WebSocket 오류, 잘못된 메시지, 상태 변경·손실은
손실 레코드를 flush한 뒤 캡처 오류로 반환한다. wire stream의 기존 동작은
유지한다. CLI의 인자 조회와 flag 확인은 공통 함수로 정리하고 중첩 분기를
읽기 쉽게 펼쳤다. 종료 시 WebSocket close 대기에 시간 제한을 둔다.

## 작은 공통 처리

대소문자 hex 출력은 하나의 alphabet 기반 인코더를 사용하고, 스크립트의
binary 출력도 같은 프로토콜 유틸리티로 처리한다. MQTT filter 검증은
중간 Vec 할당 없이 수행한다. 스크립트 invocation과 completion은 device,
session, generation을 각각 복사해서 정의하는 대신 기존 `Context`로 보관한다.
GUI의 LG 기록 reset 절차도 하나의 메서드로 모았다.

## 검증

저장소 잠금·재시작·실패 보존, 작업 취소, 캐시 갱신·scope 교체, 알림의
크기·필터·순번, 캡처 손실 처리에 회귀 검사를 적용한다. 공통 검증 명령은
`scripts/check-0.2.sh`이며 전체 테스트, strict Clippy, 8개 feature 조합,
format과 JS 문법 검사를 실행한다. GUI는 `scripts/check-gui.cjs`의 브라우저
검사로 제어·진단·세대 fencing·LG 타임라인·export를 검증한다.

실제 LG 계정이나 가전 연결은 이 리팩토링 검증에 포함하지 않는다.

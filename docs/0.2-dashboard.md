# Dashboard and packet studio

The GUI is served by the management listener with `management.gui = true` and
requires the `gui` build feature. Open `/` on that listener. Assets, fonts and icons
are local; no CDN, Materialize or external font service is required.

The dashboard uses its own responsive design with light/dark themes and four views:
Devices, LG cloud, Activity and System. Devices can be searched, filtered by status
and sorted. Cards show local connectivity, driver faults and cloud bridge state.
The detail dialog exposes properties, model identity, firmware, last-seen time,
validated property commands and explicit lifecycle actions. Destructive actions
require confirmation. Scope values remain strings to preserve 64-bit identities;
commands are disabled if the captured device session changes.

LG cloud sign-in uses the existing start/complete flow. Account inventory refresh,
per-device pairing/resume/pause/unpair and external MQTT health remain distinct
operations. System offers scoped retained cleanup with confirmation. Activity keeps
at most 100 events and reports interrupted connections.

Open a device's packet studio to inspect live traffic. It offers direction filters,
pause, auto-scroll, copy, packet analysis and JSONL export. The browser retains at
most 500 records and an 8 MiB hex-string budget. Exports preserve loss markers and
use the CLI's `packet`, `clip` and `ack` record types. Buffer eviction is explicitly
recorded. Raw injection requires both the runtime switch and a confirmation;
changed device sessions require reconnecting the monitor.

`POST /api/packets/decode` accepts `hex`, optional `direction` (`fromDevice` or
`toDevice`) and optional `model_id`. It returns detailed AABB/TLV/UART analysis and
`exportText`; `GET /api/tlv/catalog` exposes the catalog. Both are available in
API-only mode. Analysis is bounded to 65,536 packet bytes and two concurrent
workers. The CLI decoder uses the same protocol analysis implementation.

Device metadata persists model ID, display model, software version and last-seen
Unix seconds. Old schema-2 records default missing fields. LG inventory and saved
device names refresh on account/device events and explicit requests. Alias changes immediately update connected
dashboards and packet monitors, without waiting for device traffic. Cards use
reported device types for appliance icons; unknown types use a neutral device icon. Account reconciliation pauses an enabled
bridge if its registration disappears, preserving saved registration material.
An empty inventory is confirmed by a second poll after one minute before pausing.

Validation uses local Rust integration/unit tests and browser fixtures. No live LG
account or physical appliance validation is claimed.

## Reproducing browser checks

Install Playwright outside the repository, then serve the actual assets locally:

```sh
npm install --prefix /tmp/rusthinq-gui-deps playwright
/tmp/rusthinq-gui-deps/node_modules/.bin/playwright install chromium
python3 -m http.server 8765 --bind 127.0.0.1 --directory crates/rusthinq-app/assets
```

In another terminal run:

```sh
NODE_PATH=/tmp/rusthinq-gui-deps/node_modules node scripts/check-gui.cjs
```

`GUI_TEST_URL` overrides the local server URL; `GUI_TEST_ARTIFACTS` overrides the
screenshot directory (default `/tmp/rusthinq-gui-check`). The check mocks management
responses and WebSocket traffic while loading the real HTML/CSS/JS. It checks
responsive layout, themes, search/filtering, hostile text, identity precision,
stale-session fencing, confirmation, bounded activity/traffic and capture export.

## Device controls and diagnostics

The detail dialog reads accepted retained script publications via
`GET /api/devices/{id}/presentation?incarnation=…&generation=…&script_generation=…`.
All three identities must match the live device/driver. The application caches
opaque publications; only the GUI interprets IL-0 descriptors and their `x-mqtt`
state mapping. No Rhai driver or model binding is added by this UI change.

Widgets support binary switches, selection menus, bounded numbers, strings and
trigger buttons. Read-only properties show reported state. `requires` conditions
prevent a control from being submitted when its prerequisite is absent. Trigger
buttons require confirmation. Commands still enter the existing `__command`
callback and are validated by the existing driver. A queued command, completed
driver invocation and changed appliance state are separate observations; socket
writes are never presented as appliance acceptance. Advanced property entry is
available when a driver has no compatible descriptor.

Connection diagnostics show local connection counts, receive/send counts and the
last received/sent timestamp since this process started. System shows uptime,
driver faults and rejected operations. `GET /api/diagnostics` and the System download
button export a support report with version, device metadata, counters and bounded
sanitized diagnostic events. Credentials, private keys, certificates and packet or
script publication contents are excluded. Device names and IDs remain in the report.
Publication projections are bounded to 256 devices, 256 entries/512 KiB per device,
and 16 MiB total; they are ephemeral and inaccessible across session/driver changes.

## LG notification observation and correlated captures

LG cloud and packet studio offer **Start LG feed** / **Stop LG feed**. Sign in to
LG first. This read-only observer uses a separate ephemeral account client ID,
RSA CSR and client certificate. It subscribes to the account's MQTT notification
filters over verified TLS with AWS-IoT ALPN; it does not provision, register, enable
or command an appliance. Observation starts off after a daemon restart. All UI,
CLI and MCP consumers share the observer, so stopping it affects other captures.

The observer reconnects after a network failure and drops account-bound history
when authentication/account context changes. Server history is capped at 1,000
events/8 MiB; paged responses are byte-bounded. Cursors are decimal strings to retain
64-bit precision. `lost` and `reset` indicate a gap or restarted runtime. Browser
history is independently bounded; packet studio retains cloud, wire, note and loss
records within its existing 500-record/8 MiB limit.

Device IDs explicitly present in notification JSON are associated with that device.
Notifications without a recognized device ID are labeled as account events, rather
than falsely attributed to the selected appliance. A notification close in time to
a packet does not prove that packet caused it. JSONL records keep the server's
`observedAt` and the capturing client's `t` timestamp so remote clock skew does not
silently mix two clocks in the displayed capture timeline.

Management APIs:

- `GET /api/cloud/notifications?cursor=0&limit=100&device=DEVICE` returns status and
  history; `limit=0` returns status only.
- `POST /api/cloud/notifications` accepts `{"enabled":true}`, `{"enabled":false}`
  and optional `"clear":true`.
- `/api/cloud/notifications/ws?cursor=CURSOR&device=DEVICE` streams replayed history,
  new notifications, status/reset events and subscriber loss markers.

CLI examples (use the existing `RUSTHINQ_API` and authentication environment variables):

```sh
lgcloud-monitor                         # live account notifications
lgcloud-monitor --inventory             # the earlier inventory-only behavior
rusthinqctl cloud-watch
rusthinq-capture DEVICE capture.jsonl --cloud
```

`--cloud` requires a connected notification feed before opening the output file.
It captures device traffic, LG notifications and stdin annotations together. If the
LG feed loses its account context, stops or disconnects, the capture exits with an
error rather than silently continuing without correlation. The shared observer
remains enabled until explicitly stopped or the daemon restarts. Browser exports
also contain cloud records. Replay only injects receive-side packet records; it
ignores cloud/account/session records and rejects captures containing loss markers.
MCP exposes `cloud_start`, `cloud_stop` and cursor-based `read_cloud`.

Validation covers local notification MQTT handshake/subscriptions/PUBACK/cancellation,
observer certificate identity isolation, bounded history and cursor filtering,
real-driver presentation without an external broker, API scope checks and browser
control/cloud-export behavior. Live LG service and physical appliance validation
remain outside this change.

## 코드 정리와 수명 관리

저장소 공통화, 비동기 작업의 RAII 소유권, 알림·진단 캐시 및 CLI/캡처
리팩토링의 변경 범위와 종료 보장은 [0.2-refactoring.md](0.2-refactoring.md)에 정리했다.
Rhai 드라이버와 지원 모델 확장은 포함하지 않는다.

Cloud display names require a signed-in LG account and a successful account inventory
read. The inventory must contain a nonblank `alias` under a `deviceId` exactly matching
the local device ID. Per-device bridge enablement is not required. Without a matching
alias, the dashboard displays the model name/model/ID. Names are not persisted locally;
logout clears the alias cache. The Devices Refresh action also reads LG account names when signed in;
LG inventory refresh updates the same cache. Device and LG list IDs must match;
model names alone are not used to join unrelated devices.

The icon/type catalog covers all 40 numeric types in the
[wideq type inventory](https://github.com/ollo69/ha-smartthinq-sensors/blob/master/custom_components/smartthinq_sensors/wideq/device_info.py)
and [named ThinQ Connect appliance families](https://github.com/thinq-connect/thinqconnect-mcp/blob/main/thinqconnect_mcp/tools.py). Related types share an appropriate icon;
unknown types stay neutral. Bridge pairing suggestions use the same catalog.

Name refresh is requested on management server startup, dashboard/monitor connection,
local device arrival/removal/incarnation change and online/offline transitions, account
login/logout/recovery, and explicit refresh. Normal packet traffic
with unchanged device presence does not cause LG queries. One owned worker serializes
background reads. Automatic triggers within 60 seconds of the last completed LG
name query are skipped (including failed queries); no delayed re-query is scheduled.
Explicit Devices/LG list refresh and account refresh bypass this refractory period
and restart it. Logout clears the account name cache and query cooldown. Reads
are cancelled on shutdown. Account status is watched directly, including credentials restored after management
startup; names have no periodic refresh or account-status polling.

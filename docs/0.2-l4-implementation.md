# 0.2 L4 bridge foundation

The new `rusthinq-bridge` workspace crate begins with firmware/SOTA host evidence
in `firmware::Hosts`. It depends only on L1, serde_json, and the URL parser; it has
no legacy dependency, network access, global state, mutex, logging, or wall clock
in the host evidence core.
Its application/bridge owner supplies monotonic milliseconds and serializes calls.
The decision core is now connected to the L3 passthrough hook by `passthrough::Relay`.

## Firmware/SOTA host evidence

The reference does not serve firmware images itself. It learns download hosts
and routes TLS to their actual servers so appliance root/certificate checks work.
There are three evidence tiers:

- `Command`: HTTP(S) URL observed anywhere in an actual cloud-to-device JSON
  command; does not expire and cannot be weakened by reactive evidence.
- `Suspected`: URL inferred by a caller from a classified TLS failure; expires
  after 60 seconds. A live route hit renews the lease to ten minutes. Expiration
  removes the entry and allows a later local termination attempt.
- `Local`: proven local TLS/provisioning endpoint, or explicit local policy;
  overrides both remote tiers and prevents later misclassification. Successful
  local provisioning can protect HTTP(S) and `ssl://` endpoint URLs.

The core does not classify arbitrary TLS failures itself. A route hit preserves
the reference's renewal rule; it is not proof that an outbound download succeeded.
Command learning must only receive real bridge downlink traffic. Local data and
unvalidated deploy metadata are not sufficient evidence.

## Bounds and intentional changes

The caller chooses a nonzero capacity. All tiers share that capacity, including
local protection records. A full registry rejects new names explicitly; local
protection and command evidence are never silently evicted. Local protection can
replace an existing remote record at capacity. Expired suspicions free capacity.
Snapshots remove expired entries without renewing leases.

JSON scans are iterative, with limits of 4096 nodes, depth 64, and 4096 bytes per
string. Learning commits all discovered hosts together; payload/capacity failure
does not commit partial learning. Time advancement and expiry still occur before
the scan. Callers can log/report rejected learning rather than silently truncating.
Backwards or overflowing time is rejected without changing state. DNS names are
normalized to lowercase with a trailing dot removed; malformed names, IP literals,
and URLs with user credentials are ignored/rejected. URL schemes and structure
are parsed using `url`, including IDNA normalization. Nothing is dialed here.

Compared with the reference, storage and scan work are bounded, local/remote
evidence lives in one serialized state map, and expiry actually removes records.
No CDN is hardcoded, and no state is persisted automatically. Non-HTTP remote
URLs remain ignored. Applications must treat protected endpoints as policy and
must not discard the registry during ordinary session replacement.

Reference snapshot: `99c48ccc33bfc602626e0b9151b98de442185c2f`,
`legacy/0.1/crates/rusthinq-cloud/src/thinq2/firmware.rs`. Confidence precedence,
60/600-second leases, arbitrary-field URL scanning, and deploy endpoint protection
are selectively adapted. Dependencies on legacy utility locks/core logging and
Instant-based timing are removed. The reference documents false passthrough
incidents involving `kic-common.lgthinq.com`; model/firmware versions are unrecorded.
No real-device or LG-cloud validation is claimed.

Five pure tests verify nested command URLs and normalization, unsupported URLs,
lease expiry/renewal, evidence precedence, local endpoint protection, independent
registries, atomic admission, depth/node/string limits, capacity reclamation, and
clock/hostname errors. They use injected time and require no network or sleeps.

## TLS passthrough transport

`passthrough::Relay` implements L3's `Passthrough` hook. It owns a serialized host
registry, a monotonic epoch, and a shared nonblocking semaphore. Clones share the
same policy and capacity. Evidence updates are explicit methods; no inference is
automatically made from arbitrary TLS errors or device data. Configured L3 local
identities retain priority over passthrough regardless of remote evidence.

Defaults: 256 total host records, 64 simultaneous connections, 10-second outbound
connect timeout (including DNS), and no default transfer deadline. The caller
can opt into an absolute transfer timeout using Some(duration); this is not an
idle timeout. Long healthy firmware downloads are not cut off by a default deadline. Admission at capacity fails immediately without
waiting or dialing. Policy rejection fails before outbound work. A live suspected
routing hit renews its lease even if the subsequent dial fails, preserving the
reference rule. Existing relays are not forcibly closed when evidence changes;
new connections use current evidence.

`HttpsConnector` resolves the selected SNI DNS name and connects to port 443.
Firmware URL path, credentials, and port do not override the SNI transport target.
A caller can supply a `Connector` for another destination policy or a fake endpoint;
its future must not spawn detached work. Normalized names are passed to it.
`copy_bidirectional` uses bounded internal buffers, relays opaque bytes, and
propagates half-close while retaining the reverse direction. L3's PrefixedStream
replays routing bytes exactly once. No TLS termination, byte retry, or firmware
image interpretation occurs on the relay path.

L3 owns and joins the returned future. Dropping it on listener shutdown drops both
sockets and releases the semaphore permit, including during a pending connect.
No relay tasks are spawned by L4. Timeout and I/O failure release capacity and
close both sides. The front door currently reports hook errors as `Failure::Io`;
detailed policy/connect/transfer errors remain in the hook's io::Result and are
not exposed as separate front-door rejection variants.

Six tests cover configuration validation, exact fragmented ClientHello/post-hello
replay, reverse bytes after half-close, unlearned/protected host refusal without
dialing, configured local routing priority, capacity rejection, connect/transfer
timeouts, admission after timeout, and cancellation/join of established and pending
connections. Endpoints are local TCP fakes; the ClientHello is synthetic (the same
wire construction as the L3 TLS tests), not a capture or a complete firmware TLS
handshake. The host evidence tests remain pure and independent of transport.

A harness combines local ThinQ1 TLS with explicitly seeded passthrough:

```sh
cargo run -p rusthinq-bridge --example firmware_tls -- \
  127.0.0.1:8443 local.example ca.crt ca.key https://cdn.example/fw.bin
```

It loads an existing CA, protects local.example, seeds the URL as operator policy,
and exits on Enter. It neither creates CA files nor automatically contacts the CDN;
an inbound allowed SNI connection triggers the dial. Real daemon wiring must learn
from actual cloud downlink commands and confirmed local provisioning.

## Remaining integration

Cloud command learning and successful local proof must be wired by the daemon.
Real LG registration/reconnect, device-to-cloud relay, application wiring,
structured transport failure events, and real-device/cloud validation remain
pending. Firmware transport has a validated fake-endpoint path; the complete
firmware service and M2b are not marked complete.

## Device registration ownership and ThinQ1 downlink

`devices::BridgeHandle` now provides a bounded shared registration inventory and
status events. The cloud adapter calls `registered` only after establishing a
registration. Its token includes device ID, lifecycle incarnation and a separate
bridge generation. Re-enabling the same incarnation keeps the registration;
disable does not deregister it. Local bind/replacement never initiates a cloud dial.
A conflicting incarnation requires confirmed deregistration before replacement.
`deregistered` is a confirmation entry point, not an outbound LG request.

Local session bindings retain their generation high-water mark even after unbind.
Late unbind cannot clear a replacement, and an old bind cannot resurrect a closed
target. Downlinks require both the captured registration token and exact captured
local session; callers must never relabel delayed traffic with current tokens.
After confirmed deregistration, a late result cannot remove a newer registration.
The inventory is process-local: its owner must stop cloud tasks before replacing
the entire registry; tokens are not restart-persistent capabilities.

ThinQ1 downlink validates enabled state, binding, current L3 session, bounded JSON
and any provided Header device ID before dispatch. JSON objects retain their
original bytes and unknown fields. A supplied firmware Relay learns only through
this validated cloud-adapter context. Host evidence admission failure is explicit
and prevents dispatch; capacity must be assessed against real appliances. Learning
proves observation of a command, not successful device delivery: later transport
queue/write failure may leave legitimate command evidence in the registry.

Dispatch uses L3's generation-targeted bounded send queue and returns its receipt.
Sent means a complete frame write, not device acknowledgement. Offline, disabled,
stale, malformed and capacity failures are explicit; no buffering, retry, reconnect
or remote dialing is hidden in this API. Cloud authentication remains the calling
adapter's responsibility. This path does not emit retained MQTT publications.

Four tests cover shared bounded state, disable/re-enable registration preservation,
replacement and late-result fencing, offline high-water marks, broadcast loss and
snapshot recovery, real framed local transport byte preservation, invalid/disabled
targets and firmware learning admission. Tests use duplex local transports and
synthetic JSON; no LG cloud or real-device compatibility is claimed.
Actual cloud transport, uplink ACK ownership and provisioning
proof integration remain pending. M1/M2b remain incomplete.

L4 now defines a cancellation-safe `Deregistration` adapter boundary. L6 executes
it during bridge-aware Forget and applies successful confirmation to the captured
registration token before durable device removal. Error/timeout preserves the
registration and quiesced device for explicit retry. The adapter implementation
for actual LG requests is still pending; integration tests use fake cloud adapters.

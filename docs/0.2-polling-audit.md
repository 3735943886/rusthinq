# Polling and timer audit — updated 2026-10-17

Scope: workspace runtime, management GUI, LG bridge and tools. The audit distinguishes
state-change detection from protocol liveness, remote reconciliation, retry deadlines,
and sampled telemetry. Timer removal must preserve subscription-before-snapshot,
current session/incarnation fencing, stream-loss recovery, and owned shutdown.

## State detection converted to notifications

| Area | Previous work | Current trigger and correctness boundary |
| --- | --- | --- |
| Driver hot reload | Read and parse every active source bundle every second. | `notify` native filesystem events; 200ms bounded save debounce. Access/unrelated-file events are ignored. Initial fingerprints and changed-event scans share bundles by selected driver. Compilation failure preserves the current scope. Capacity rejection alone schedules a 250ms retry. |
| Generation reservation | Wake the core every 100ms to inspect the server budget. | A coalescing watch signals every generation allocation, including unidentified ThinQ1/MQTT connections and ThinQ2 reprovisioning. Subscribe before reading the budget. Burst coalescing is safe because the owner reads the latest high-water mark, not an event count. Both standalone and mixed transports use the same signal. |
| External MQTT | Every second, revisit inventory/cache to test a 30s ping deadline; unrelated application events also caused full passes. | State/scope/durable-ledger changes and output/removal queues drive reconciliation. Ping uses a fixed deadline in a separate idle wait; a ping or transient publication does not itself rescan retained state. The deadline is also checked between publication batches so continuous work cannot reset it. |
| MQTT scope validation | Clone all devices, script states and durable entries for individual publications while holding the publication cache. | Read the requested device from an indexed snapshot and inspect its scope/durable membership without copying global projections. Recheck validity after every blocking ledger write and before sending; never carry a validity result across I/O. |
| Bridge supervisors | Offline/stale-bind tasks wake every second, clone/search all devices, and react to unrelated packet events. | Wait on coalesced device/scope state, account client/cancellation, or shutdown signals. Read only the requested indexed device. Existing packet subscriptions remain for connected relay traffic. Closed state/account channels terminate the supervisor instead of spinning. |
| Device controls | Fetch full presentation every 2s while a dialog is open. | Initial open, selected-device script events, stream reconnect/loss, and visibility restoration invalidate the presentation. A bounded 50ms event batch and dirty flag preserve changes arriving during an HTTP read. Existing scope checks fence stale controls. |
| Login/MQTT status | Fetch cloud, MQTT and health every 5s (15s hidden). | `/api/services/ws` subscribes to account/MQTT status watches before its initial invalidation. The browser refreshes on invalidation and coalesces changes arriving during a request. Reconnect supplies a fresh invalidation. No periodic cloud-status reads. |
| Capture readiness | Up to about 180 local HTTP status reads at 250ms intervals before opening the notification stream. | Enable once, open the stream immediately using the returned cursor, then await its initial snapshot/status transitions with a single 45s deadline. No status-poll/socket handoff gap. Capture starts after connected is confirmed. |
| Setup success output | Sleep 1.5s solely to keep a success message visible. | Removed; there is no device operation to await at this point. |

Previous corrections remain: name-cache refresh is triggered by startup, GUI
connection, presence changes, explicit requests and account status watches. Its
60s refractory period limits repeated remote reads; it is not a periodic poll.
Bridge inventory results are shared with the name cache instead of re-querying LG.

## Timers retained deliberately

| Timer | Why a deadline/period is required | Bounds and optimization |
| --- | --- | --- |
| LG inventory reconciliation, 15min | There is no verified reliable remote-registration deletion event. A device-state notification does not prove account membership. Without reconciliation, a registration removed through the official LG app could remain enabled locally indefinitely. | The timer is enabled only for an authenticated account with current, enabled saved registrations. Login/account changes and management commands also request an immediate check. No periodic wake or remote read when no relevant registration exists. Reconciliation pauses missing registrations and preserves pairing material. |
| Empty inventory confirmation, 60s | A transient empty LG response must not immediately pause every saved registration. A second, separated empty result confirms account-wide absence. | Only after the first suspicious empty result, and only while relevant registrations remain. Account changes reset the confirmation. |
| MQTT liveness probe, 30s | The output connection needs to discover a half-open/failed broker even when there is no application output. Its CONNECT currently declares keepalive zero, so this is an application liveness probe, not a claim that the broker mandates a 30s ping. | A fixed `sleep_until` deadline and bounded PINGRESP exchange replace the 1s poll. Unrelated events cannot reset the deadline. Idle probes do not traverse the retained cache. |
| Dashboard telemetry, 30s | Uptime is elapsed time, and cumulative diagnostic/drop counters do not have a complete revision stream. Sending a WebSocket message for every packet counter would create more traffic. | Sample local health/MQTT counters every 30s instead of fetching all services every 5s. Skip network reads when the tab is hidden. Login and connection state remain event-driven. |
| Deferred driver admission, 250ms | A capacity rejection does not expose a guaranteed admission-ready notification. Dropping the edit would lose a requested reload. | Retry only while an edit is deferred; no timer after success/failure or during ordinary idle watching. |
| Reconnect backoff | A network failure produces no guaranteed future event indicating that the peer/network has recovered. Immediate loops would hammer a failing endpoint. | Attempt-driven bounded backoff (exponential where configured); dormant during healthy operation. Account cancellation and shutdown interrupt waits. |
| Credential expiry, MQTT/RTI keepalive, I/O and operation timeouts | These represent elapsed-time protocol or failure boundaries, not unchanged-state polling. | Sleep directly to the relevant deadline. Preserve bounded I/O, cancellation and ownership/join guarantees. |
| `releaseDev` setup delay | This configurable delay sequences an appliance setup exchange; it is distinct from the removed cosmetic pause after success. | Applied only to that setup operation, not an always-running timer. |
| UI debounce, toast/download cleanup | Coalesce an actual event or bound a displayed/resource lifetime. | One-shot timers, not repeated reads of unchanged state. |

The 15min/60s membership intervals preserve the existing remote-read policy: at
most 15min ordinary detection delay, with a separated confirmation before treating
an empty account as authoritative. They are not documented LG API requirements or
measured optimal values. The 30s telemetry period is a UI freshness/traffic policy,
not a correctness dependency; interactive state transitions use notifications.

## Validation

Regression coverage includes refill after an unidentified admission without advancing
virtual time, fixed MQTT ping under continuous unrelated events, stream-based capture
readiness with no HTTP status poll, service invalidation without device traffic, native
watch atomic saves/module removal, and preserving the previous scope on compile failure.
The browser check asserts an unchanged open dialog/account is not polled and that a
script-output event does request fresh presentation data. Existing scope fencing,
retained cleanup/recovery, cloud-registration reconciliation and shutdown tests remain
part of the workspace checks. These checks establish behavior; no production CPU or
latency improvement is claimed without measurements. Native watcher execution is
verified on Linux; Windows/macOS backends are supplied by `notify`.

# Polling and timer audit — 2026-10-04

Scope: workspace runtime, management GUI, LG bridge and tools. This is a source audit;
remaining findings have not been changed or certified by appliance tests.

## Corrected

- Name-cache 15-minute LG polling is removed. Startup, GUI connection, device
  presence changes and explicit requests remain triggers, with the existing
  60-second refractory period and explicit refresh bypass.
- Name-cache 5-second account-status polling is replaced with the account owner's
  status watch. Idle management no longer wakes merely to check login state.

The necessary bridge registration reconciliation now shares successful account
inventory results with the name cache, without an additional name query. Explicit
management reads publish through the same account-fenced result channel.

## Remaining candidates

| Location | Finding | Suggested direction |
| --- | --- | --- |
| `assets/panel.js` | Open details fetch presentation every 2 seconds; service health/account/MQTT every 5 seconds (15 when hidden). Device WebSocket does not currently carry all these projections. These are local HTTP reads, not LG reads. | Emit publication/service revision events, then fetch only changed projections; avoid deleting timers before equivalent notifications exist. |
| `src/runtime.rs` | While generation refill is configured, a 100ms wake repeatedly checks the server's reserved generation budget. | Notify the runtime when admission consumes the low-water budget; account for unidentified connections, which do not necessarily emit a device Up event. |
| `src/cloud_devices.rs` | Supervisors already watch device/account events but also wake every second while offline or after stale bind. | Audit whether all invalidating transitions emit events, then remove redundant wakeups; handle closed receivers explicitly. |
| `src/external_mqtt.rs` | A recreated 1-second sleep checks a 30-second ping deadline inside select. Repeated non-writing events can keep resetting that sleep, delaying a needed ping. | Select directly on the fixed ping deadline and verify behavior under continuous local events. |
| `src/driver_watch.rs` | Each second, fingerprints sources separately for every attached device, even if multiple devices share a driver. | Deduplicate scans by source bundle; filesystem notifications are a separate portability/design choice. |

Additional tool findings:

- `rusthinq-tools/src/capture.rs::cloud_events` polls local notification status
  every 250ms for up to 45 seconds before opening its WebSocket. The notification
  stream already reports status changes; opening it first and waiting for connected
  would eliminate up to roughly 180 status requests and the handoff race.
- `rusthinq-tools/src/bin/rusthinq-setup.rs` sleeps 1.5 seconds solely to keep a
  success line visible before printing another line and exiting. This is a UX
  pause, not a device requirement, and is removable. Its separate configurable
  `releaseDev` delay serves appliance setup sequencing and needs different review.

## Timers with distinct responsibilities

- `cloud_devices.rs` performs another 15-minute LG inventory reconciliation:
  remotely removed registrations are disabled and their supervisors stopped.
  The one-minute second check confirms an empty account result. This is not name
  refresh. Removing it without a remote-deletion signal loses that behavior.
  It currently queries even when there are no relevant enabled registrations;
  skipping those reads is a narrower optimization candidate.
- LG MQTT/RTI keepalive, credential expiry/renewal, reconnect backoff and I/O
  deadlines have protocol or failure-handling purposes. They are not equivalent
  to periodically re-reading an unchanged projection.
- GUI toast/download cleanup timers are resource/display lifetimes.

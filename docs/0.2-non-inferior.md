# 0.2 non-inferior acceptance audit

The acceptance standard is preservation of successful 0.1 appliance flows and
capabilities, with improvements permitted. Byte-for-byte reproduction of bugs is
not required. Bounded queues, strict parsers, and deadlines need evidence that
they do not reject valid existing use. Unit/integration success alone does not
establish full non-inferiority or production readiness.

## Corrected normal-flow risks

- MQTT keepalive: the original 0.2 implementation could disconnect a client after
  1.5 times a short declared interval (or 90 seconds for zero). The 0.1 broker
  explicitly preserves a 300-second floor because appliances can remain idle
  beyond nominal keepalive. 0.2 now uses max(300 seconds, configured timeout,
  1.5 times declared keepalive) after CONNECT. Pre-CONNECT admission retains its
  bounded configured timeout. Pure interval tests and a virtual-time session test
  cover the grace floor without five-minute test sleeps.
- Firmware passthrough: an unconditional 30-minute transfer limit could truncate
  a healthy large/slow download. The default is now no transfer deadline, matching
  the preserved raw relay flow. An optional absolute deadline remains available
  to callers. Connect timeout, bounded buffers/connections, and listener-owned
  cancellation still bound admission and shutdown. Tests cover optional timeout
  and default half-close/reverse-data behavior.

Reference: `99c48ccc33bfc602626e0b9151b98de442185c2f`,
`legacy/0.1/crates/rusthinq-cloud/src/mqtt_broker.rs` (idle_timeout_for), and
`legacy/0.1/crates/rusthinq-cloud/src/thinq2/sni_passthrough.rs` (raw relay).
The broker reference records appliance idle observations without exact model or
firmware versions; new tests are synthetic and do not claim real-device validation.

- QoS1 DUP: the prior 0.2 runtime disconnected on valid retransmission. It now
  acknowledges and forwards through L1 using the reference's at-least-once
  semantics, including first-seen DUP and packet-ID reuse. No unsupported
  application-level deduplication is inferred from transport IDs. Same-transport redeploy is now supported with fresh logical generations and
  queued-send fencing; enforced wire ACK correlation remains unimplemented.

- Empty MQTT client ID: clean connections now accept an empty ID, as in the
  reference broker. Transport admission and validated ThinQ2 device IDs preserve
  independent sessions and targeted commands. Persistent sessions remain pending.

- Will CONNECT options are now accepted and validated. Abnormal termination emits
  a raw Will observation; clean and administrative shutdown suppress it. Subscriber
  publication, retained storage, and downstream QoS remain open gaps, so this is
  not yet full Will non-inferiority.

- QoS2 ingress now performs PUBREC/PUBREL/PUBCOMP and dispatches once per completed
  transaction within a clean connection. This corrects the reference's positive-QoS
  PUBACK shortcut. Durable sessions and outgoing QoS2 remain pending.

## Remaining scope and order

Five open areas remain below; they are not five similarly sized changes. Complete
MQTT publication/session capabilities and the current TLS/HTTP/firmware compatibility
checks first, then resume L4 registration, evidence wiring and relay integration.
Global non-inferiority also depends on later application/scripts/adapters and live
appliance evidence; it cannot be certified from these foundation tests alone.
Do not call L4 complete or erase known gaps to satisfy the sequencing preference.

## Open compatibility gaps

| Area | Current limitation | Required validation/completion |
| --- | --- | --- |
| Device MQTT | Limited packet/session subset; Will subscriber delivery/retention, persistent sessions, retained handling and outgoing QoS1/2 remain unsupported | Audit reference capabilities and representative appliance traffic; implement required flows |
| TLS identity | Preconfigured names; dynamic leaf issuance/fallback excluded | Show deployed endpoint/registration coverage or restore required issuance with bounded ownership |
| ThinQ1 HTTP | Stricter XML validation and explicit metadata overload | Replay representative valid appliance requests, including unusual formatting; verify retry behavior |
| Firmware policy | Bounded host records and explicit admission errors | Validate capacity sizing and observable recovery without evicting protected local names |
| Bridge/application | Registration, downlink learning, local-proof wiring, scripts, persistence and daemon composition incomplete | Implement end-to-end existing flows and compare outputs/state transitions |

Session fencing, joined shutdown, and bounded parsing have targeted regression
tests. They are improvements within tested scenarios, not proof that every legacy
appliance or deployment remains supported. Keep milestone gates open until their
existing feature and real-device requirements are met.

## Retained publication deletion requirement

Every retained MQTT publication must have an explicit removal route before it is
enabled: a recorded owner and exact topic, individual deletion, owner-wide cleanup
for device/adapter removal, and complete namespace cleanup. MQTT remote deletion
uses an empty-payload PUBLISH with RETAIN=1. Local map deletion, unsubscribe,
connection closure, and device offline do not prove remote retained deletion.
Removal work must survive remote failure and restart until delivery is confirmed;
persistent adapters must store the cleanup inventory/pending tombstones durably.
A QoS0 socket write alone is not broker confirmation. Reconnect, mapping changes,
and disable/remove flows must drain or recover cleanup work, not silently abandon it.

`rusthinq-server::retained::Store` now provides bounded owner/topic inventory,
empty-payload removal, individual/owner/all cleanup manifests, and owner-scoped
replay. Tombstones encode empty RETAIN=1 packets. It is an in-memory foundation,
not a remote publisher or durable cleanup queue. Owned retained network publication now goes through the durable inventory and
matching PUBACK path in L6; daemon lifecycle orchestration remains pending. Will retain metadata likewise remains an observation
until this publication/deletion path exists.

The retained cleanup foundation now includes a versioned, bounded recovery ledger
and per-attempt result fencing. Storage ownership remains L6: a serialized checkpoint
is not itself proof of durable persistence. File commit and remote MQTT confirmation
must be wired before enabling network retained publication.

L6 now implements local durable file commits and recovery in
[application foundation](0.2-l6-implementation.md). A deletion-only MQTT session now correlates PUBACK and commits completion.
Owned retained publication now commits its ownership inventory before network writes.

Retained empty-payload deletion now has an acknowledged remote route. Nonempty
retained publication now requires durable ownership inventory. Explicit individual,
owner-wide and complete removal are implemented; daemon removal hooks remain pending.

L2 `Removed` is now correlated to owner cleanup through an incarnation-scoped
device owner. This prevents late removal from deleting a recreated device's topics.
The full daemon action loop and automatic retry scheduling remain pending.

L6 now persists the actual L2 lifecycle ledger and a generation floor that survives
removing the last device. Restore starts saved devices offline; storage effects
return correlated results after durable commit. Admission-before-save crash handling,
0.1 state migration and full daemon wiring remain open acceptance requirements.

L6 cleanup now has a sequential startup/removal drain entry point. Every next
remote delete waits for the previous matching PUBACK and durable completion;
partial failure/restart retains exactly the unconfirmed and unsent work. General
retained publication remains gated on lifecycle inventory/publish integration.

The L6 ThinQ1 runtime now executes real session lifecycle transitions and durable
ledger writes. Tests cover replacement fencing, offline restart, bounded broadcast
loss reconciliation, grace deadlines and failed storage commits. This is additional
composition evidence, not real appliance compatibility proof. Admission-to-save
crash recovery, complete forget orchestration, scripts and M1's GUI flow remain open.

Local ThinQ1 Forget now quiesces, awaits generation-targeted transport completion,
and commits durable removal before emitting Removed. Tests verify peer closure,
new incarnation after recreation, and no Removed on commit failure. Cloud
deregistration remains pending; removal events use the incarnation-scoped durable
cleanup route through the optional runtime worker below.

An optional L6 runtime worker now performs retained cleanup after durable local
device removal and recovers orphan device incarnations from inventory at startup.
It preserves known offline devices and adapter owners, confirms every deletion
with PUBACK, and leaves unconfirmed work durable on failure. Tests exercise failure
followed by restarted recovery. Automatic MQTT reconnect, cloud deregistration and
runtime publication commands remain pending; this is not full M1 acceptance.

Failed retained cleanup can now recover in the same L6 runtime by attaching a
fresh connected session and reopened durable inventory. A live worker cannot be
replaced; rejected/shutdown attachments release their resources. Current cleanup
health is available through a watch snapshot even if an observer missed the
failure event. Automatic dialing/reconnect scheduling remains pending.

L4 now separates cloud registration ownership from inbound local sessions.
Disable/re-enable preserves registration, local replacement does not dial, and
old downlink/unbind/deregistration tokens cannot affect successors. ThinQ1 downlink
dispatch preserves original JSON bytes and learns firmware hosts only from valid
cloud-adapter context. Four fake-transport tests cover these boundaries; real LG
registration, reconnect and uplink remain unimplemented; bridge-aware Forget now
has the adapter execution boundary described below.

L6 bridge-aware Forget now executes close completion, a cancellation-safe L4
deregistration adapter, and durable removal in order. Registration tokens fence
late confirmation and retries; disabled registrations are also deregistered.
Error/timeout preserves the quiesced device and blocks Removed/retained cleanup.
Three fake-adapter tests cover ordering, failure/retry, cancellation and successor
protection. Actual LG request transport and restart recovery remain pending.

L6 can now reserve transport generations durably before admission; L3 enforces
the returned range for ThinQ1 and ThinQ2, including redeploy. Restart skips the
whole prior block even when no session ledger update committed. Four tests cover
reservation/restart, I/O failure and exhaustion. The lifecycle harness uses this
path. Automatic block extension, incarnation reservation and unfinished Forget
recovery remain open; the default unreserved transport mode is not crash-safe.

The ThinQ1 L6 runtime can now refill generation ranges before exhaustion using
the serialized durable storage worker. Only a committed contiguous block extends
L3; failure keeps the prior ceiling and stops automatic refill. Two integration
tests cover continued live-session operation, lifecycle-write serialization,
repeated extensions and failed commits. MQTT exposes the extension primitive but
its automatic supervision is now available in the MQTT runtime below. Slow storage/rapid churn can still
exhaust a range; no universal admission or full crash-recovery guarantee is claimed.

L6 now supports the local ThinQ2 MQTT lifecycle with the same persistence, grace,
retained cleanup and automatic generation refill logic. MQTT transport completion
is tracked through redeploy for safe Forget; two wire-level fake-transport tests
cover redeploy, durable removal/refill, raw forwarding, EOF and offline restore.
The shared transport owner below now provides mixed lifecycle/allocator execution;
production daemon and real appliance/cloud validation remain pending.

ThinQ1 and MQTT can now share one transport registry, allocator, admission bound,
stop signal and L6 lifecycle/storage owner. Two mixed tests verify cross-protocol
replacement without incarnation change, codec fencing, durable refill, isolated
Forget and shared shutdown. A plain two-listener harness is runnable. This does
not validate 0.1's multi-socket appliance flows; replacement remains an acceptance
risk requiring captures/real-device evidence. TLS/provisioning and full M1 remain open.

The mixed L6 owner now has a supervised two-listener TLS composition. Two tests
perform verified TLS handshakes and real device packets, then check pending
handshake cancellation, transport/runtime joins and storage-lock release.
The harness loads an existing CA and explicit SNI identities. Provisioning,
metadata/script/GUI wiring, RTK/no-SNI deployment configuration and appliance
validation remain open; these TLS tests do not establish complete compatibility.

Additional ThinQ1 HTTP/provisioning TLS listeners can now share the L6 supervisor.
ThinQ1 metadata reaches a bounded latest-observation snapshot/event without creating
a false online device. Three tests cover TLS XML delivery, advertised MQTT port,
listener/signer shutdown, capacity/update rejection and final queue drain. HTTP
queue acknowledgement is not durable metadata persistence. Model/driver binding,
metadata persistence/correlation and unknown-record reclamation remain open risks.

L5 now has an IL-agnostic bounded Rhai execution foundation with ordered opaque
outputs, explicit disabled publication, fault isolation and generation reload.
The archived ThinQ1 synthetic round-trip baseline passed and matches the fixed
reference hash. This is not a real-model fixture; real driver selection, ctx/module
compatibility, timer/runtime wiring and full M1 acceptance remain open.

The L5 blocking worker now bounds queued work plus unconsumed results, reports
overload explicitly, serializes generation-fenced reload, and joins after finishing
the current call and cancelling queued requests. Six worker tests verify these
behaviors, independent fault recovery and native panic isolation off async threads.
This improves isolation evidence but does not establish real-device non-inferiority:
L6 output dispatch and a daemon-wide admission policy remain open.


L6 now owns workers with a finite per-runtime budget, including retiring workers
until joined. Results are fenced by device incarnation, session generation,
attachment identity and script generation against the current lifecycle snapshot.
Four tests reject results after reconnect, removal, reload and same-session
reattachment. Runtime lifecycle updates invalidate workers and normal shutdown
joins them. Automatic driver selection/callback dispatch, sink delivery and real
appliance validation remain open; this foundation does not complete M1.

L6 now admits live compiled script attachments and configured transport callbacks.
Results dispatch in device invocation order after L3 snapshot reconciliation and
L2/script fencing. Send preserves the opaque JSON string through existing L3
validation/framing, with explicit write receipts; publish uses a bounded explicit
sink and does not claim downstream delivery. Five real-frame ThinQ1 tests verify
round-trip output, disabled sink faulting, sink overload, non-replayed fault prefixes,
successor reaping and ordered bursts. These scripts are synthetic. Actual MQTT
retained sink integration (including durable inventory/deletion), ctx compatibility,
timers/lifecycle callbacks and real-appliance validation remain open.

Mixed script sends now choose ThinQ1/MQTT encoding from the captured session's
protocol; unrelated registries are rejected before runtime start. Optional hex
callback input preserves binary ThinQ2 status bytes; invalid UTF-8 in default mode
rejects before execution without faulting or changing scope. Four integration tests
cover both codecs, binary data and redeploy fencing, registry mismatch and healthy
progress after UTF-8 rejection. MQTT script downlinks are explicitly non-retained.
The external retained sink and ctx-based real-driver compatibility remain pending.

Live L6 reload now preserves the old script/scope on external compilation failure,
rejects stale session/generation requests and starts fresh scope on successful
replacement. Faulted scripts recover explicitly without replaying emitted prefixes.
Four tests cover these boundaries, successor protection and shared mailbox
overload/queued shutdown cancellation. The actor waits for bounded worker reload;
response loss/cancellation is not rollback and must not trigger automatic retry.
Actual ctx-based drivers, lifecycle/timer APIs, external retained sink and appliance
validation remain open. This adds no retained MQTT publications.

The ctx/text callback subset now preserves device-local state across calls with
explicit key/value/complexity budgets, rejects custom/reference state that could
bypass accounting, and resets on reload. Native ctx output methods remain opaque
and share the existing consumer/output bounds; L6 validates ctx target identity.
Five L5 tests and one real-frame L6 test provide evidence for state isolation,
accounting, copied values, output bounds and generation replacement. Exact heap
limits, full legacy ctx/IL helper adaptation, modules/lifecycle/timers and real-model
acceptance remain open. No raw or retained MQTT publishing API is introduced.

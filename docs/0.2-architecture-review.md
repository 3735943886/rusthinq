# 0.2 boundary audit — 2026-10-02

M0 acceptance remains open. Repeated user instructions authorized implementation,
but they did not establish completion of the architecture review. Preparation and
implementation proceeded before the planned M0 gate. This sequencing deviation is
recorded here rather than treating existing code as approved contracts or marking
M0 complete retrospectively.

## Review work still required for M0

This audit verifies the reported boundaries; it is not the complete six-part review.
The following owners and tests are evidence inputs for that review, not unchecked
assumptions of acceptance.

- H1/H7: L2 Model owns device/incarnation/removal decisions; L3 registry owns live
  sessions; L4 owns LG account policy; L5 owns workers and IL execution; L6 stores
  lifecycle/model/credential checkpoints; the MQTT adapter owns broker connection
  and retained delivery. Complete the audit of public AppHandle payloads, adapter
  service handles and compile-time dependency boundaries.
- H2/H3: script generation and incarnation fencing, compile-before-reload and
  ordered completion are exercised by `tests/scripts.rs`, `tests/runtime_scripts.rs`
  and `tests/drivers.rs`. Review preparation/timer/admission policy placement
  before accepting the thin L6 contract. A file split is not a policy move.
- H4/H5: lifecycle and management integration tests cover admission versus durable
  removal, failed persistence, stale commands, broadcast loss reconciliation and
  joined shutdown. The retained ledger preserves unknown broker outcomes. Account
  policy tests cover priority logout and cancellation; storage tests preserve
  saved credentials on already-stopped startup. Pairing intent storage exists but
  per-device pairing/forget integration remains open.
- H6: `lg_compat` contains the baseline and explicit RTK TLS profile; fake HTTPS
  pairing tests verify that the server trust CA need not issue the client identity.
  Finish representative ThinQ1/ThinQ2 fixture selection and record compatibility
  exceptions. Live appliance/account validation is excluded by user instruction.
- Intentional changes: non-inferiority supersedes exact 0.1 equality, but it does
  not waive documented behavior review, migration, unsupported feature combinations
  or missing GUI bridge controls. Review the contracts' intentional changes
  individually against reference fixtures before closure.
- Scenario walk: connect/status, unknown command outcome, late generation close,
  reload failure/panic, unconfirmed forget and unknown compatibility profiles need
  a final owner/input/output/failure table that includes the composed cloud paths.
  Cloud sockets/reconnect and pairing management are not implemented, so that final
  table cannot yet establish acceptance.

## Configuration and build contract

Daemon user configuration is UTF-8 TOML, bounded to 64 KiB. Duplicate keys,
unknown fields and invalid types are rejected. Parse errors do not echo source
text or secrets. Paths remain relative to the configuration file. JSON configuration
is rejected; JSON management payloads and existing internal checkpoint encodings
are unchanged. Translate the configuration into TOML before using the new binary.
See [runtime](0.2-runtime.md) and [operations](0.2-operations.md) for examples.

The currently supported compile-time configurations are default (`gui`) and
`--no-default-features` (API only). Both still include bridge and scripting code.
This is partial implementation of the contract, not M5 build-combination acceptance.
The next structural task is optional bridge/scripting dependencies and removal of
all references to disabled capabilities from the corresponding build.

Validation for these corrections: 263 workspace tests passed; all-target workspace
Clippy passed with warnings denied; formatting and diff checks passed. The API-only
build passed `cargo check -p rusthinq-app --no-default-features`, and its TOML
configuration test confirmed omitted GUI defaults to false and explicit GUI
activation is rejected. These checks do not establish optional bridge/scripting
builds or M0/M5 acceptance.

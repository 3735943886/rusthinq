# L2 lifecycle foundation

`rusthinq-lifecycle` is a new independent workspace crate with no dependencies.
It does not use the L1 crate or legacy source. `Model` loads a supplied ledger,
consumes lifecycle inputs with monotonic elapsed time, and returns ordered
actions, an explicit error, and the earliest offline deadline. L6 will run it and
execute its effects. No clocks, files, sockets, threads, waits, or executors are
present in the model.

## Session and availability decisions

Each device has a persistent incarnation and generation high-water mark. New
generations replace the current session and emit a close effect targeting the
old session. Stale down events must match both incarnation and generation and
otherwise do nothing. An equal/older session-up is rejected. The runtime must
assign generations greater than the loaded ledger's high-water mark; a counter
resetting to zero at process startup is not compatible with this contract.

A matching down event clears the usable session immediately and schedules the
offline report after the configured grace. Reconnection before expiry cancels
the deadline without an offline/online transition. At the exact deadline, offline
is emitted before processing the incoming event. Zero grace reports offline in
the same input. Loaded devices start offline without sessions. Backwards time
returns an error without mutating state; counters are checked for overflow.

The ledger retains the next-incarnation high-water mark even when empty, so a
forgotten identity can later register with a new incarnation. Live snapshots
include current session, reported online state, grace deadline, and removal
progress; ledger snapshots contain only persistent identity/generation data.

## Forget sequence and results

Forget immediately quiesces the device: clears its usable session, cancels grace,
and reports offline. It then emits correlated effects in this order:

1. Close the captured session (or perform an idempotent close when already offline).
2. Deregister from LG only if the initial forget request captured an active bridge.
3. Persist a removal ledger.
4. Emit Removed only after the matching persistence success result.

Results must match device ID, incarnation, operation ID, and step. Duplicate,
late, wrong-step, and previous-incarnation results are ignored. Every step has
a distinct failure event and a visible failed state; the device stays quiesced.
No timer retries it. A new explicit forget request retries only the failed step
with a fresh operation ID and the original bridge choice. An overlapping request
returns Busy. New sessions for a quiesced device are rejected and receive a close
effect targeted to their generation. Other devices continue normally.

## Persistence contract for L6

Storage effects have one model-owned in-flight slot. Registration/replacement
marks the ledger dirty; updates arriving during a write coalesce into one dirty
flag. Pending removals remain in per-device state and dispatch by operation order,
with priority over a general dirty snapshot. Snapshots are constructed only when
dispatched. A removal snapshot excludes only its own target, retaining other
pending or failed removals. A matching result frees the slot; unissued, stale,
and duplicate results cannot advance the sequence.

After a failed removal write, a later ordinary snapshot includes the failed
quiesced device. Another device's update cannot silently confirm that removal.
After a successful removal, subsequent snapshots exclude the removed device.
Failures never trigger automatic retries; a new explicit forget request retries
its failed step. Ordinary write failures do not roll back live sessions.

L6 must execute emitted storage effects once, use atomic replacement, and report
completion only when no write for that effect is still in flight. An unknown
outcome may still differ from live state until a later successful write. The
model bounds pending storage correlation to one slot plus one dirty flag; no
per-update queue or growing set of pending revisions remains.

Quiescence before the storage step is live state only. Restart restores the last
successfully written ledger, not an unfinished close/deregistration operation.
Crash recovery of unfinished forget operations and migration from 0.1's storage
format remain L6/M2a work, rather than an implied guarantee of this model.

## Verification and scope

Eleven deterministic sequence tests cover session replacement and late close,
offline grace and exact deadlines, local/bridged forget ordering, every failure
and explicit retry, result correlation, independent-device progress, ledger load
and write failure, incarnation reuse protection, serialized concurrent removal snapshots, coalesced updates, unissued results,
invalid ledgers, and counter/time errors. All workspace tests, formatting, and
Clippy with warnings denied pass.

L2 is a new implementation of the L2 contract in `0.2-contracts.md`. No code was
copied from legacy. The contract's explicit quiescence, conditional deregistration,
and partial-failure outcomes are implemented here; existing 0.1 removal behavior
is not claimed to be preserved. Storage adapters, runtime ownership, and real
device validation are not implemented. M0/M1/M2a remain incomplete.

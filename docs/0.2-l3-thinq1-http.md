# 0.2 L3 ThinQ1 HTTPS/XML foundation

`rusthinq-server::thinq1_http::Service` implements POST routes through the TLS
front door. Each connection serves one HTTP response and closes. The standalone service
is now also routed alongside ThinQ2 provisioning by `https::Service` on one listener.

- `/lgehadm/api/Device/TotalDeviceInfoSvc`: default `0000/OK`,
  `DM_SETTING_INFO_GET_URI` BlackBox=N, and `THINQ_TIME_SYNC_URI` UTC time with
  timezone=0, preserving the reference XML envelope and element ordering.
- `/lgehadm/api/Grid/PowerSavingInfoSvc`: `0108/No Saving Data.`
- `/lgehadm/api/Rtos/FWInfoSettingSvc`: `0000/OK` acknowledgement only.
- `/lgehadm/report/diagmon`: empty success response.

Known routes require POST (405 otherwise); unknown paths retain the reference
200 JSON `{}` fallback. TotalDeviceInfo requires `x-lgedm-deviceid` (256-byte
limit). An optional device type must be nonempty and at most 128 bytes.

When modelName and device type are present, the service admits a `Metadata`
observation into a bounded channel. It owns no device store and does not publish
online/readiness state. L6 must consume, correlate, and persist observations.
A full or closed receiver returns 503 rather than silently losing metadata.
Admission precedes response delivery; a disconnected HTTP peer can therefore
leave an admitted observation. Consumers must tolerate repeated requests.

The UTF-8 XML parser requires a single lgedmRoot, rejects DTDs, unknown entities,
illegal characters, nested field markup, repeated fields, and malformed XML.
It decodes ordinary/numeric entities and CDATA. Depth is bounded at 16 and
recognized field content at 1024 bytes. Default body limit is 1 MB, metadata
capacity 64, body timeout 10 seconds, and connection timeout 30 seconds. HTTP
headers are bounded at 32 and the parser buffer at 8 KB. Oversized bodies return
413, invalid requests 400, body timeout 408, and unavailable clocks 503.
FrontDoor bounds admission and cancels/joins active connections on shutdown.

Reference snapshot: `99c48ccc33bfc602626e0b9151b98de442185c2f`,
`legacy/0.1/crates/rusthinq-cloud/src/thinq1/http.rs`. Only wire response strings
and route behavior are selectively adapted; there is no legacy dependency.
Intentional changes: malformed XML is rejected, metadata delivery has explicit
backpressure, and item requests work without modelName (the reference's substring
parser accidentally gated items on modelName). Metadata storage and firmware
downloads are not imported. These synthetic TLS fixtures are not device captures
or real-device validation; model/firmware evidence is unrecorded.

Five HTTPS integration tests cover exact XML responses, metadata entities/CDATA,
malformed input and field limits, missing device ID, bounded/closed receivers,
method/fallback behavior, Content-Length/chunked body limits, timeouts, and joined
shutdown. Run the harness with an existing CA:

```sh
cargo run -p rusthinq-server --example thinq1_http -- \
  127.0.0.1:8443 local.example ca.crt ca.key
```

Add `rtk` only for the explicit RTK_RTL8711am compatibility profile. The example
prints metadata and exits on Enter; it does not create or overwrite CA files.
Firmware serving, persistent metadata, daemon composition, and real L4 bridge
work remain pending. This foundation does not complete M1 or M2b.

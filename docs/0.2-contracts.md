# 0.2 Architecture Contracts — Design Hardening

Status: concrete design proposals for review, not implemented behavior or a claim of user
approval. These resolve structural questions at design level; the review items at the end
remain explicit. See [decisions](0.2-design.md) and [milestones](0.2-milestones.md).

## H1 — Ownership and Ordering

Use an application-owned per-device controller, separate from the socket session. It survives
socket replacement and serializes semantic device work. A registry owns controller handles
and device identity; it does not execute scripts or wait on network/storage operations.

| State | Sole writer | Other access |
| --- | --- | --- |
| Device registration and incarnation | Registry | Immutable device-list projection |
| Current session generation, grace deadline | Device controller's pure lifecycle model | Session receives generation token |
| Protocol parser, ACK state, transport deadlines | Session-owned protocol core | Typed inputs/outputs only |
| IL descriptor, values, descriptor revision, semantic operation status | Device controller | Immutable application snapshots |
| Rhai decoding state and AST generation | Owned script worker for that device | No direct external access |
| Script timer names/generations | Device controller | Runtime executes deadlines; worker requests changes |
| Durable metadata and credentials | Storage service, through explicit operations | Registry/controller get completion results |
| MQTT retained inventory and cleanup backlog | MQTT adapter/storage | Application sees integration status |

“Application owns IL state” means the per-device controller is part of the application, not
one global mutable property map. Registry/GUI/MQTT views are projections, never independent
command-validation authorities. A replacement controller receives a new incarnation so its
counters cannot collide with events from a forgotten instance.

Each device processes one semantic invocation at a time. Commands are validated immediately
before invocation against committed descriptor/values. Descriptor publication is committed
before the next command can be validated. Queue order is the ordering contract; independent
input producers do not imply a global physical-time order.

## H2 — Script Invocation and Output Contract

Run synchronous Rhai code in bounded blocking execution owned by the host; do not execute it
on the registry or transport loop. One invocation per device may be in flight. Retain Rhai
operation/memory limits and require native host functions to be bounded and nonblocking.
Aborting a Tokio wait does not stop a blocking closure: shutdown must request cooperative
cancellation and observe worker completion. A stuck native call cannot be promised a hard
in-process kill deadline.

The neutral sink collects a bounded, ordered invocation output batch: descriptor/value/event,
device send, timer change, and explicit optional MQTT extension requests. The worker returns
the batch; it never publishes or writes a socket. Exceeding the output budget fails the
invocation instead of silently dropping outputs.

The controller validates the entire returned batch before committing semantic updates and
reserving bounded downstream send capacity. If admission fails, report failure without
sending frames or committing the batch. After commit, device sends execute in recorded
order. Transport failure cannot roll back already committed semantic events or bytes sent;
report that distinction. Never infer device state from a queued write unless the script
explicitly reports it. This is not a distributed transaction.

On an invocation error, panic, invalid batch, or failed batch admission, discard unpublished
outputs and mark the script generation faulted: its mutable decoding state may have changed.
Cancel its timers, reject new semantic commands, expose unavailable/absent state according to
IL rules, and emit diagnostics. Require an explicit reload to create a fresh generation;
neither reconnect nor an automatic supervisor retries the failed invocation. Protocol
transport may continue independently, subject to bounded input limits. This fault behavior
and output batching are intentional changes from immediate 0.1 publish/send callbacks.

Protocol ACKs remain in the session core and do not wait for Rhai. AABB local auto-ACK versus
LG-relayed ACK is an explicit single-owner policy; never emit both for one frame. Script
requests to change that policy take effect at an acknowledged session input boundary, not
retroactively for a frame already processed.

## H3 — Commands, Replacement, and Reload

Command results distinguish rejected/busy, accepted, queued for transport, sent, and, only
where supported, device-confirmed. A disconnect after partial transmission is an unknown
outcome, not a safe automatic retry. Client timeout is not cancellation of bytes already sent.

On socket replacement, the controller installs a new session generation and invalidates old
session-dependent work. It may process lifecycle invalidation while a script is running, but
cannot launch a second invocation. A returned batch carrying an old generation is discarded;
the stale worker state is retired rather than reused. The old session cannot update current
availability. A protocol-defined new connection can initialize a new driver; it cannot clear
a recorded panic fault automatically.

Compile a reload candidate outside the controller. Compile failure leaves the old generation
active. For successful compilation, wait for the current invocation to settle, cancel old
timers, install a fresh driver generation, clear unverified semantic values, and run startup
hooks through the same batch contract. Do not copy opaque Rhai state across generations.
Startup failure faults the new generation; no automatic rollback/restart is implied.

Keep transport-online, script-health, and IL availability distinct. Reconnect grace may defer
the UI offline indication, but cannot keep writable semantic state falsely current after a
known disconnect. Apply IL A-2/R-4 unavailable/absent behavior at disconnection. Label any
historical UI values explicitly and do not use them for command preconditions.

## H4 — Subscription, Pressure, and Shutdown

An application projection service serializes committed updates into a revisioned read model.
It provides an atomic subscribe-plus-snapshot handoff: register the bounded receiver and
capture revision R under the same owner; deliver only subsequent revisions. Lag requires a
fresh snapshot. Commands always validate at the controller, not against this projection.

Command queues are bounded: reject new requests as busy when capacity is unavailable. Raw
monitor streams are separately bounded and loss is observable. Do not silently discard
protocol/driver inputs; if a device cannot be processed within its capacity budget, fail that
session explicitly rather than indefinitely blocking a shared broker loop. State publication
failure cannot silently leave the projection permanently stale: mark it unavailable and
rebuild from controller snapshots before serving it again.

Shutdown stops admission, cancels timers, invalidates generations, resolves pending callers,
closes transports, and joins owned work. Control/cancellation signals have a path independent
of full data queues. No restart supervisor is introduced. Exact queue sizes are tunables;
overflow semantics are architectural contracts.

## H5 — Forget and Partial Failure

Treat forget as removal of the current registration, not a permanent device ban. Serialize
it through the registry, quiesce the controller, invalidate its incarnation, stop commands,
and close its sessions. Persist removal of local metadata/pairing and a durable MQTT cleanup
record before reporting durable completion. A storage failure is visible and leaves the
operation failed/quiesced; do not report forgotten or silently restart the device.

MQTT retained cleanup may be pending while the broker is unavailable. Report local removal
and adapter cleanup separately. Adapter reconnect reconciliation of durable cleanup is an
explicit transport policy, not an application retry of a failed command. Device-send and
panic retries remain prohibited. Any remote LG cleanup has a separate reported outcome.

Do not admit the same identity during removal. A later connection may register it anew with
a new incarnation. Old retained cleanup must settle before new retained publications for that
identity, so a delayed delete cannot erase new state. Detailed file/journal format is an
implementation choice; crash recovery of these stages is mandatory.

## H6 — LG Compatibility Boundary

Use a pure `lg_compat` module for evidence-backed exception selection and transformations,
not a catch-all constants file or a new plugin engine.

| Observed example / source | Classification and owner |
| --- | --- |
| ThinQ1 framing and `process_one` ACK envelope | Protocol core; record unknown fields without inventing meaning |
| AABB auto-ACK and suppression of LG ACK relay (`scripting/ctx.rs`) | Protocol policy with one ACK owner; selection through typed host/session input |
| TLS1.0/CBC support for RTK_RTL8711am (`cloud/certs.rs`) | Compatibility policy applied by the TLS runtime before device identity is available |
| Per-SNI certificate handling (`cloud/certs.rs`) | TLS server service; explicit hostname policy, not semantic device state |
| Model property decoding | Rhai driver, governed by IL contracts |

TLS policy selection cannot depend on metadata learned after the handshake. Preserve the
required device-listener compatibility explicitly; do not silently broaden unrelated API or
outbound TLS settings. Protocol profiles can use authenticated/observed metadata available at
their actual selection point. Unknown matches use the documented baseline or explicit
unsupported outcome; never guess by applying every known workaround.

Assign stable LG-* IDs with observed model/firmware, evidence/source, known versus inferred
meaning, applicability, behavior without the workaround, and fixture/validation. Missing real
captures remain marked unverified. Runtime-specific TLS objects stay outside the pure module.

## H7 — Dependency Layout

Initial target: a dedicated `rusthinq-core` containing protocol/lifecycle models and pure
compatibility policy; a `rusthinq-app` library containing controllers, services, runtime and
script hosting; and the daemon binary composing these with adapters. GUI and MQTT adapters
consume the public AppHandle contract and do not become dependencies of the application.
CLI/MCP online paths use the management API; offline analysis may reuse pure codecs.

Dependency direction: daemon -> adapters/app; adapters -> app; app -> core.
No app -> GUI/MQTT implementation edge, no core -> app edge, and no legacy dependency.
Keep runtime/application modules in one crate initially rather than split them into cyclic
crates. Existing pure utilities may be copied into core or a small utility crate after review.

## Evidence and Pre-Implementation Review Gate

Inspected paths in the current tree: `scripting/ctx.rs`, `scripting/il.rs`,
`scripting/scripted_device.rs`, `scripting/engine.rs`, `cloud/device_control.rs`,
`cloud/certs.rs`, and the sibling IL normative rules. Paths abbreviate their existing crate
prefixes. Code inspection establishes current behavior, not validation of this new design.

Before legacy relocation or implementation, review these intentional changes explicitly:

- Batched script outputs and faulting on invocation/admission failure rather than immediate
  publication and continued execution; replay representative script fixtures to assess compatibility.
- Fresh state on reload and semantic invalidation immediately on disconnect despite UI grace.
- Forget closes/quiesces live sessions and exposes partial completion instead of unconditional success.
- Raw MQTT compatibility remains an optional capability; when disabled, surface an explicit
  unsupported-capability error rather than silently claiming publication succeeded.

Architectural decisions H1–H7 now have concrete proposed answers. They remain design-review
items until accepted; do not label them tested or implemented. Choose and record the actual
ThinQ1 script and pinned IL/script fixture revisions before M1. Full tool inventories, endpoint
spelling, numeric queue capacities, and storage encoding do not block architectural review.

never be obtained. D140110's pinned bodies are AABB frames with no platform evidence;

Real-CSR, route, bound and shutdown tests pass, and `tls_runtime.rs`/`runtime_mqtt.rs` cover the composed daemon path through driver attachment.
- [x] Audit and migrate firmware service dependencies; verify existing response behavior. Command learning, local proof and the raw relay are wired and tested. The 2026-10-03 audit found that 0.1's retry path was missing: 0.1 suspected `https://{sni}/` after a failed local TLS accept, so an appliance retry passed through even when no command named the host. Restored by choice (a): `Relay` refuses an SNI name with no evidence and marks it suspected (60 s, renewed on use), so the retry passes through. Local proof and command evidence are never weakened. `unlearned_host_is_refused_then_suspected_and_protected_hosts_never_dial` covers this. As in 0.1, any name reaching the front door can be relayed to its real port 443 after one retry.
- [x] Audit SNI passthrough ownership/routing/shutdown and verify the preserved path. The daemon composes one `Relay` as the L3 hook; configured local names take priority, protected/unlearned hosts never dial, and bytes relay unchanged with half-close. `passthrough.rs` and `tls.rs` cover capacity, timeouts, panic containment and cancel/join on shutdown. Intentional change: no per-SNI certificate minting (see L3).
- [x] Exercise local-only and bridge-enabled ThinQ2 paths and record any unavailable real-device validation. Local-only: `tls_front_door_runs_real_thinq2_mqtt_session_without_an_external_broker`, `runtime_mqtt.rs`. Bridge-enabled: `bridged_thinq2_device_relays_through_fake_lg_cloud_and_falls_back_to_local_acks` (`tests/cloud_bridge.rs`) runs a local ThinQ2 appliance through the daemon's TLS front door, `tls_runtime::Service`, the cloud owner and a fake LG service. The fake service is the HTTP account API through the feature-gated `test-support` seams `Client::with_test_service` and `account::Runtime::with_client_factory`, plus TLS MQTT. Over three cloud sessions it verifies OAuth refresh, enable, preDeploy/Ready, ACK hand-over (no local ACK while bridged), byte-exact uplink (mid/kind restamped as in 0.1) and downlink, local ACK fallback on cloud loss, prompt reconnect, and no dial after logout. It found two defects, both now fixed. A cloud disconnect unbound the still-live local session, so `bind` returned `Stale` and the supervisor exited: the device never reconnected to LG until disable/enable. The reconnect backoff also never reset (0.1 resets it after a successful connection). Reverting either fix fails the test. Real appliances are excluded.

Exit criteria: each server service has a documented owner and a validated retained or migrated

## Working Principles

- Reference decision IDs in implementation changes instead of repeating their rationale here.
- Import legacy components only as needed, recording provenance and verifying their new dependencies.
- Keep the new root entry point runnable as features land; retain the fixed reference for comparison rather than refactoring it in parallel (D0).
- Separate selective component reuse from intentional behavior changes in reviews.
- Resolve structural uncertainty in M0; use implementation evidence to refine details without silently changing accepted contracts.
- Estimate the remaining work after M1 demonstrates the actual migration cost.

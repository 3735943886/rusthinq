## Current delivery status — 2026-10-02

Layer foundations (L1–L6) are not milestone acceptance. The composed daemon now
serves a broker-independent management API/dashboard, automatically prepares
model drivers, and optionally routes script output through an external MQTT
adapter. Eleven pinned real model drivers initialize; focused fixtures exercise
AABB commands/status, TLV timer effects, and publication/deletion through a fake
external broker. Property commands now enter through a separate authenticated MQTT
subscriber, with retained/duplicate rejection and generation-fenced script admission.
Real-appliance and LG-account validation are excluded at the
user's request; implementation gaps remain tracked rather than waived.

The latest implementation verification passed 257 workspace tests, warning-free
Clippy for all targets, formatting, JavaScript syntax and diff checks. See
[operations](0.2-operations.md) for deployment contracts.
Non-inferiority remains the standard; exact 0.1 equivalence is not required when
the behavior improves without losing supported capabilities.

   production MQTT output and one supported command. Every retained publication

## M2a — Shared Lifecycle and Script Services

- [ ] Move device replacement/offline policy to its explicit owner and verify late close/timer sequences (C3, R1).
- [ ] Migrate script timer/runtime ownership and reload ordering; reject outputs from replaced script generations (R3, S1). Owned timers, explicit/file reload and fenced on_drop now exist; broader reference sequence comparison remains open.

Automatic driver watch has local-MQTT integration evidence: file changes replace
and initialize a fresh generation; syntax errors preserve the old generation;
a corrected file replaces it without a panic-retry loop. The watcher is bounded,
owns preparation tasks and joins on daemon shutdown.

Terminal-hook evidence covers active-call completion/queued cancellation, fault
containment, exactly-once publication for a disconnected session, rejection after
replacement, and prohibition of device sends. A composed TLS/daemon/fake-broker test
withholds the terminal PUBACK and verifies the daemon keeps MQTT alive until it is
confirmed. Retained ownership/deletion survives these availability updates.
- [ ] Move IL helpers, command validation, and descriptor/value state from the host into Rhai (D1); coordinate the rusthinq-scripts changes.
- [x] Connect persistence/recovery and removal operations; specify failure outcomes and durable versus live state. Incarnation-scoped model metadata now shares the serialized durable ledger writer; restart, removal, stale-owner and schema migration tests pass.
- [ ] Connect bridge management and outbound reconnect policy without adding panic recovery machinery (R4, P1).
- [ ] Verify new paths have no dependencies on legacy callbacks, global mutable lifecycle services, or state owners.

Exit criteria: migrated sessions and script services have explicit lifecycle owners and pass

## Working Principles

- Reference decision IDs in implementation changes instead of repeating their rationale here.
- Import legacy components only as needed, recording provenance and verifying their new dependencies.
- Keep the new root entry point runnable as features land; retain the fixed reference for comparison rather than refactoring it in parallel (D0).
- Separate selective component reuse from intentional behavior changes in reviews.
- Resolve structural uncertainty in M0; use implementation evidence to refine details without silently changing accepted contracts.
- Estimate the remaining work after M1 demonstrates the actual migration cost.

# rusthinq 0.2 compatibility inventory

Every externally visible 0.1 surface, classified under C4 as **preserve**, **change**
(intentional, with a migration note) or **retire**. Wire protocols toward appliances and
the LG cloud are preserved and recorded separately (L1 compatibility table, non-inferiority
audit). Reference: `legacy/0.1` at `2473c34683130c29ad2f07d560d15b2c94342a36`.

`rusthinq-migrate OLD_CONFIG DEST` stages a converted installation without touching the
original and lists every setting that needs review in its report `warnings`. See
[tool migration](0.2-tools-migration.md) and [operations](0.2-operations.md).

## Configuration (`config.toml`)

| 0.1 key | Class | 0.2 / migration note |
| --- | --- | --- |
| `hostname`, `ca_key_file`, `ca_cert_file` | preserve | Same meaning; paths become absolute in the staged config |
| `https_port`, `mqtts_port`, `thinq1_port`, `thinq1_https_port` | change | `https_bind`, `mqtt_bind`, `thinq1_bind`, `thinq1_http_bind` socket addresses with 0.1's `address`; a port without `bind` is not bound. ThinQ1 HTTP defaults to 46030 as in 0.1 |
| `advertise` (port or URL) | change | `https_advertise`, `mqtt_advertise`; as in 0.1 only `/route` uses them |
| `http_port` | change | `http_bind`: plain HTTP with the HTTPS routes, for a TLS-terminating proxy |
| `custom_root_cert_file` | change | `custom_root_certificate`, served by `/route/certificate` |
| `advertise_requested_host` | preserve | Same key and meaning (DNAT setups) |
| — (0.1 device TLS profile) | preserve | 0.1 always served TLS1.0+/`SECLEVEL=0` to devices; the migrator sets `legacy_tls = true` |
| `log` | retire | Warning; 0.2 writes application events to stderr |
| `mqtt_enabled` | change | `false` means no `[external_mqtt]` is written (warning) |
| `[mqtt] mqtt_url`, `mqtt_user`, `mqtt_pass` | change | `[external_mqtt]` host/port/tls/username/password, enabled, with the imported retained inventory as its ledger |
| `[mqtt] rusthinq_prefix` | preserve | Becomes `[drivers] topic_prefix` |
| `[mqtt] state_file` | change | Converted to the schema-2 retained inventory under explicit legacy owners; cleanup only on request |
| `[mqtt] raw_prefix`, `raw` | change / retire | Injection streams (`inject`, `inject_clip`, `emit`) set `management.raw_inject = true` for the `$raw` routes; observation streams are retired (warning) |
| `[bridge] storage_path` | change | Account refresh credentials convert; per-device registrations are archived for `bridge/adopt` |
| `[bridge] dns` | change | `bridge_dns`: DoH URLs or plain DNS servers for every outbound LG cloud connection, including firmware passthrough |
| `[scripting] rhai_dir`, `watch` | preserve | Become `[drivers] directory`, `watch` |
| `[scripting] il_prefix` | retire | Warning naming the old value; the host has no IL setting. IL scripts choose the descriptor prefix (rusthinq-scripts `il_common.rhai` `prefix()`, default `il`) |
| `[gui] gui_port`, `gui_user`, `gui_pass` | change | `[management] bind`, `user`, `password`. As in 0.1, authentication is optional on any bind |

0.2 rejects unknown configuration fields at startup, so a 0.1-style key added by hand
fails loudly instead of being ignored.

## MQTT

| 0.1 surface | Class | 0.2 behavior |
| --- | --- | --- |
| `<prefix>/<id>/<prop>` retained values | preserve | Published by the scripts via `ctx.publish_raw`; the host only routes and inventories them |
| `<prefix>/<id>/<prop>/set` | change | Delivered unvalidated to `on_set_property`; validation and rejects are the scripts'. Retained and duplicate QoS1 sets are discarded |
| IL descriptor `<il_prefix>/<id>` | change | Script-owned; 0.1 default was off, `il_common` default is `il` |
| Retained cleanup | change | Durable inventory per owner; exact/owner/all deletion with PUBACK confirmation, surviving restart. Broker reconnect republishes the latest retained state without clearing it; a script reload removes only topics the new generation no longer publishes |
| Non-retained output during a broker outage | change | Dropped and counted (`droppedTransient` in `GET /api/mqtt`); never replayed late and never fails the script |
| Bridge control topics | change | Reserved `<prefix>/<id>/$bridge/{pair,enable,disable,unpair}/set` envelopes with captured `incarnation` |
| Raw bus `<raw_prefix>/<id>/raw/rx|tx`, `raw/inject/set` | retire / change | Streams are retired; observation moves to the management monitor and `rusthinq-capture`. Injection moves to `$raw/{inject,emit}/set` with captured identity, `inject_ok:true` and `management.raw_inject=true` |

## Persisted state

| 0.1 file | Class | 0.2 |
| --- | --- | --- |
| `known_devices.json` | change | Schema-2 device ledger with fresh incarnations, preserving model/platform metadata |
| MQTT property inventory (both 0.1 formats) | change | Schema-2 retained inventory; no deletion intent is created by migration |
| Account (bridge storage) | change | `account.json`; tokens renew automatically |
| Per-device cloud registrations | change | Archived; adopted per device with `POST /api/devices/{id}/bridge/adopt` after confirmation against the LG account; imported disabled |
| CA key/certificate | preserve | Reused in place |

Migration never edits the 0.1 files. Rollback is stopping 0.2 and restarting 0.1 on the
untouched originals.

## Rhai host API

| 0.1 | Class | 0.2 |
| --- | --- | --- |
| `id`, `model_id`, `model_name`, `sw_version`, `device_topic`, `state_get`/`state_set`/`state_has`, `set_timer`/`cancel_timer`, `send_raw`/`send_clip`/`send_json`, codecs (`hex_*`, `tlv_*`, `aabb_*`, `json_*`) | preserve | Same calls; state and outputs are bounded |
| `publish_raw(topic, payload, retain)` | preserve | Native opaque primitive (S3); the only MQTT-shaped call |
| `publish_il`, `publish_property`, `publish_event` | retire (host) | Provided by rusthinq-scripts `il_common` as `il::publish_*(ctx, …)` |
| Host command validation before `on_set_property` | retire (host) | Drivers call `il::validate` themselves |
| `set_auto_ack` | retire | ACK policy belongs to the protocol core (L1) |
| `length_prefixed_make`, `length_prefixed_make_str` | retire | The host frames ThinQ1; no driver used them |
| — | new | `is_thinq2`, `state_remove`, `bytes_utf8`, `base64_*`, `crc16` |
| `import "<name>"` modules | change | Same syntax; static names only, resolved from the driver directory into a bounded bundle at preparation, with no filesystem access while running |
| Callbacks `start`, `publish_config`, `on_data`, `on_response`, `on_timer`, `on_drop`, `on_set_property` | preserve | Invoked per device in order; a superseded generation cannot emit |
| Test harness `d.descriptor()` | change | `d.published(topic)`; the harness interprets no script semantics |

Scripts are not interchangeable across the boundary. 0.2 needs the rusthinq-scripts
`il_common` revision, because 0.1-era drivers call `ctx.publish_il`. The 0.1 runner fails
on that revision (11 drivers publish no descriptor). Rolling back therefore also means
checking out scripts at `54292921c6edc72ea6ec901b1137845bff14e6ae`, which passes its 187
tests on 0.1.

## HTTP and GUI

| 0.1 route | Class | 0.2 |
| --- | --- | --- |
| `/`, `/panel.js`, `/monitor`, `/monitor.js`, assets, `/ws`, `/device` | preserve | Served by the management endpoint; no external MQTT needed |
| `/bridge/{id}/enable`, `/bridge/{id}/disable` | change | `/api/devices/{id}/bridge/{pair,enable,disable,unpair,adopt}` with captured incarnation |
| `/forget/{id}` | change | Same path; requires the captured incarnation |
| `/thinq_login`, `/thinq_login_accept`, `/thinq_logout` | change | `/api/cloud/login`, `/api/cloud/login/complete`, `/api/cloud/logout` |
| — | new | `/api/devices`, `send`, `invoke`, `reload`, `inject`, `/api/events`, `/api/mqtt`, retained deletion |

## Capture and tools

0.1 JSONL captures are read unchanged by `rusthinq-capture`/replay; replay feeds ordered
rx input only and never retransmits captured outbound or cloud commands. Command-line
replacements are listed in [tool migration](0.2-tools-migration.md).
